RAG Pipeline

Important: this simulator uses a deterministic, browser-based embedding approximation so you can see the mechanics. Production RAG would normally use a real embedding model such as an OpenAI, Cohere, Voyage, or open-source embedding model.
📄

1. Document Ingestion

RAG starts with information the LLM should be able to retrieve later.

Ready
What's happening?
In a real RAG system, ingestion may include PDFs, websites, database records, support tickets, policies, product documentation or APIs. Before retrieval can happen, the system needs to prepare this data.
✂️

2. Chunking

Large documents are divided into smaller retrievable units.

Waiting
Process the document to generate chunks.
PM insight: Chunk size is a product and technical tradeoff. Chunks that are too small can lose context. Chunks that are too large can retrieve too much irrelevant information and consume more context-window tokens.
🧬

3. Create Embeddings

Each chunk is converted into a numerical representation of meaning.

Waiting
Embeddings appear after the document is processed.
An embedding might actually contain hundreds or thousands of numbers. To keep this simulator readable, we display only a short vector. Similar meanings should ideally appear near each other in embedding space.
🗄️

7. Top-K Retrieval + Reranking

Keep the strongest candidates and optionally reorder them with a second scoring step.

Waiting
Top-K results will appear here.
Why rerank?
Vector similarity gives you candidate chunks quickly. A reranker can perform a more precise second-pass comparison between the query and retrieved chunks, potentially improving retrieval relevance.
